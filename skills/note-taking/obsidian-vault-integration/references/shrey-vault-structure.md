## ⚠️ Critical Path Bug — search_files on Windows Vault Paths

`search_files` (ripgrep-backed) **silently returns zero results** on Windows paths with spaces. This vault is under `E:/_Knowledge/` — spaces throughout.

**Always use terminal grep for content searches in this vault:**
```bash
terminal cd "E:/_Knowledge/ObsidianVault" && grep -rl "pattern" . --include="*.md"
```

The file tool works fine with quoted absolute paths — only `search_files` is broken on space-containing paths.

## Bidirectional Linking Convention

When creating a new hub note, link in **both directions**:

**In the new note body:** `[[Related Note]]` wikilinks in context  
**In each linked note:** append to `## Related Notes (Backlinks)` section

```markdown
## Related Notes (Backlinks)
- [[New Hub Note]] — One-line description of connection and relevance
```

The exact section label for this vault is `## Related Notes (Backlinks)` — multiple backlinks accumulate in it. Never just link from the new note and skip the back-references. The user specifically checks for this.

## MOC Update Checklist

When adding a new note, update in this order:

1. **Immediate topic MOC** — `00_<topic>_MOC.md` in the note's folder. Add entry, bump `Files:` count, update `Updated:` date.
2. **Area-level MOC** — Confirm the topic MOC is linked from the area `00_<area>_MOC.md`. Usually already done.
3. **Area FILE_INDEX** — Check footer. If it says "Auto-generated by Topic Organizer", SKIP.
4. **All linked notes** — add reciprocal back-reference to each note the new note links to.

## ⚠️ delegate_task Research Agent Failure — 2026-07-15

All 5 research agents (TN, Kerala, Karnataka+AP+Telangana, cross-state, extended belt) timed out at 600s on slow web search APIs. Session compiled manually using direct `terminal curl` calls.

**Lesson:** Never rely solely on `delegate_task` for live web research. The 600s timeout is too short for web search + synthesis loops. When research is needed:

1. Use `terminal curl` directly to Wikipedia API (`https://en.wikipedia.org/w/api.php`) — reliable, fast
2. For academic: arXiv API or direct DOI lookups
3. Compile content directly in session, then `write_file` to vault
4. `delegate_task` is fine for: reading existing files, multi-document synthesis, parallel processing of already-fetched data

**Correct pattern for vault-based research:**
- Read existing vault notes first (they contain the baseline)
- Pull only what the vault is missing via direct API calls
- Compile and write directly — don't round-trip through agents for web research
