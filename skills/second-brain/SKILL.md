# Second Brain (/SB command)

When the user sends `/SB` (with or without a query), treat it as a request to query their second brain — the Obsidian vault.

## Recognising the command

The command may arrive in any of these forms:

- `/SB <query>` — search the vault for `<query>` and return the most relevant notes.
- `/SB` (no query) — list the top-level folders of the vault and offer common next steps.
- `/SB help` — show a quick help message with usage examples.

If the user's message starts with `/SB` (case-insensitive), extract everything after it as the query (trim whitespace).

## Vault path

The vault is cloned from `https://github.com/pshreyas77/MYOBSIDIAN-VAULT` at container startup and lives at `/vault` inside the running environment.

Always treat `/vault` as the absolute vault root. Do not use environment variables when calling file tools — resolve to `/vault/...` directly.

If `/vault` does not exist or is empty, tell the user the vault isn't synced yet and suggest waiting for the next sync, or running `cd /vault && git pull` (only mention the path, never execute arbitrary user-supplied shell commands).

## Behaviour

1. **Parse the command.** If no query follows `/SB`, list the top-level folders using `search_files(target="files", pattern="*", path="/vault")` and reply with a short inventory and a one-line prompt like "Send `/SB <topic>` to search."

2. **Search the vault.** For a query like `/SB aerodynamics`, run `search_files(target="content", pattern="<regex>", path="/vault", file_glob="*.md")` to find matching notes. Use case-insensitive patterns where helpful.

3. **Open the top hits.** Read the top 3 most relevant notes with `read_file(path="/vault/<relative_path>")`.

4. **Compose the answer.** Reply with:
   - A short summary (2–4 sentences) that synthesises what the vault says about the query.
   - A bulleted list of the matching notes with their relative paths (e.g. `02 - AREAS/Aerodynamics Notes.md`).
   - For each note, include one quote or one-line excerpt that makes the hit useful at a glance.
   - If the query was empty, show the folder inventory instead.

5. **Stay concise.** Telegram messages render best under ~1500 characters. If there are many matches, show the top 5 and offer to dig deeper with `/SB <refined query>`.

## Safety

- Only **read** from `/vault`. Do not write, edit, delete, or move notes — that requires explicit `/SB edit <path>` or similar, which this skill does not implement.
- Never execute shell commands the user pastes. Only run the search/read tools above.
- Do not expose internal paths outside the vault (e.g. `/home/hermes/...`); always present paths relative to `/vault` or as Obsidian-friendly wikilinks `[[Note Name]]`.
